# 출처 이용 조건 기록

기획안 §11에 따라 출처별 이용약관·접근 허용 범위·재배포 범위를 확인해 남기는 문서다. **확인 전에는 수집하지 않는다.**

**담당** 정책 출처는 B, 뉴스 출처는 A. 기록 양식과 판단 기준은 공통으로 쓴다.
**관련 이슈** #2 (정책 출처·수집 기간·이용조건 확정), 완료기준 C1

## 1. 지켜야 할 선

- 로그인·유료·접근제한을 **우회하지 않는다**
- 출처가 안내한 호출 제한과 수집 간격을 따른다. 실패해도 과도하게 재시도하지 않는다
- **열람·수집 가능 여부**와 **재배포 가능 여부**를 구분해 판단한다. 읽을 수 있다고 다시 배포할 수 있는 것은 아니다
- 공개 저장소에는 공개 가능한 메타데이터·집계값·샘플만 넣는다. 원문 전문은 `data/raw/` 에 두고 추적하지 않는다
- 불필요한 개인정보를 수집하지 않는다
- **제공자가 기계적 수집 경로를 닫은 출처는, 다른 경로로 대체 수집하지 않는다**
- **출처를 등록할 때 최신 글 날짜를 확인한다.** 페이지가 열리는 것과 자료가 갱신되는 것은 별개다. 최신 글이 수집 기간과 겹치지 않으면 등록해도 쓸 수 없다

끝의 두 항목은 작업 중에 추가했다.

- 세 번째 항목의 근거는 §4의 정책브리핑 사례다
- 네 번째 항목의 근거는 2026-10-17 수집 시험이다. 과기정통부 RSS 3종을 "페이지가 열린다"는 이유로 모두 `terms_ok` 로 올렸으나, 실제로 돌려 보니 2종의 최신 글이 2022-02-09과 2026-03-27이어서 77건이 전부 기간 밖으로 제외됐다. 접근 가능 여부를 확인할 때 갱신 여부를 함께 보지 않은 것이 원인이다

## 2. 확인 상태 표기

| 값 | 뜻 |
|---|---|
| `unverified` | 접근 경로를 확인하지 않음 |
| `access_ok` | **페이지가 열리고 목록을 읽을 수 있음**을 확인. 약관은 별개 |
| `access_ok_stale` | 열리지만 갱신이 멈췄거나 매우 느림 |
| `terms_ok` | 약관까지 확인하고 수집·이용 범위가 정해짐. **수집 가능** |
| `terms_ok_local` | 수집·분석은 가능하나 **공개 산출물에 원문 텍스트를 포함할 수 없음.** 집계 수치와 URL·발행일만 공개 |
| `blocked` | 약관 또는 결정에 따라 수집하지 않음 |

**2026-10-17 결정 반영 후 상태**

| 상태 | 곳 | 대상 |
|---|---|---|
| `terms_ok` | 4 | 과기정통부 **보도자료**, 백악관 OSTP, NSF, DOE |
| `terms_ok_local` | 2 | 중국 국무원 영문판, 중국과학원 영문판 |
| `access_ok` | 1 | KISTEP (PDF 확인 대기, 이슈 #31) |
| `access_ok_stale` | 3 | 과기정통부 과학기술정책·주간동향(갱신 중단), 중국 과학기술부 영문 |
| `blocked` | 1 | 정책브리핑 (제외 결정) |
| `unverified` | 5 | NIST, Federal Register, 중국 과기부 중문, NDRC, 뉴스 자리 (1단계 범위 밖) |

**1단계 수집 대상은 6곳이다** (`terms_ok` 4 + `terms_ok_local` 2). 2026-10-17 수집 시험에서 과기정통부 2종이 갱신 중단으로 빠졌다.

## 3. 국가별 저작권 판단 기준

세 나라의 기준이 서로 달라, 같은 잣대로 판단할 수 없다.

### 한국 — 공공누리(KOGL)

저작권법 제24조의2(공공저작물의 자유이용)에 따라, 공공누리 표시가 **부착된** 자료는 별도 허락 없이 이용할 수 있다. 유형별 조건이 다르다.

| 유형 | 조건 |
|---|---|
| 제1유형 | 출처표시 (상업적 이용·변경 가능) |
| 제2유형 | 출처표시 + 상업적 이용금지 |
| 제3유형 | 출처표시 + 변경금지 |
| 제4유형 | 출처표시 + 상업적 이용금지 + 변경금지 |
| AI유형 | 인공지능 학습용 데이터로 이용 가능. 단 유사 산출물 방지 조치, 직접 인용 시 출처표시 조치, 학습용 데이터 재판매 금지 |

**중요** 표시가 **부착되지 않은** 자료는 자유이용 대상이 아니며 담당자와 사전 협의가 필요하다. 유형은 **자료마다 다를 수 있어** 건별로 확인해야 한다.

제1~4유형은 출처(발행연도, 기관명, 홈페이지 URL, 작성자명이 표시된 경우 그 성명)를 반드시 표시해야 한다.

### 미국 — 연방정부 저작물

미국 연방정부가 작성한 저작물은 미국 저작권법(17 U.S.C. §105)상 저작권 보호 대상이 아니어서 대체로 자유롭게 이용할 수 있다. **다만 예외가 있다.**

- 계약자·수탁기관이 작성한 부분
- 기관 로고·상표 (NSF는 Brand Standards로 별도 규율)
- 제3자가 저작권을 가진 사진·그림

NSF의 Policies 목록(`nsf.gov/policies`)에는 저작권 전용 안내가 없다. **건별 확인이 필요하다.**

### 중국 — 명시적 재배포 금지

국무원 영문판(`english.www.gov.cn`) 푸터에 아래가 명시돼 있다.

> All rights reserved. The content (including but not limited to text, photo, multimedia information, etc) published in this site belongs to www.gov.cn. Without written authorization from www.gov.cn, such content shall not be republished or used in any form.

**서면 허가 없이는 재배포하거나 어떤 형태로도 이용할 수 없다**는 문구다. 중국과학원 영문판도 `Copyright © 2002 - 2026 Chinese Academy of Sciences` 표시만 있고 이용 허락 조건이 없어, 기본값은 무단 이용 불가다.

**판단 필요** 문구의 "used in any form" 범위가 넓어, 제목을 공개 저장소에 올리는 것조차 안전하지 않을 수 있다. §6에 선택지를 정리했다.

**구현 시 처리할 것 4가지**

1. 피드 1회 응답이 **50건**. 그 이전 자료는 목록 페이지 페이징이 필요
2. `pubDate` 가 `2026.10.15` 형식. 데이터 사전의 `YYYY-MM-DD` 로 변환 필요
3. `content:encoded` 본문에 **한글(HWP) 메타데이터 JSON이 혼입**. 정제 단계에서 제거 규칙 필요
4. 목록에 **담당자 이름과 연락처가 노출**. 기획안 §11에 따라 수집·저장하지 않는다

**제외를 권고하는 이유** 제공자가 **저작권 보호를 사유로 기계적 수집 경로(RSS)를 스스로 닫았다.** 같은 자료를 HTML 스크래핑으로 대체 수집하는 것은 제공자의 의도에 반할 소지가 크다. 꼭 필요하면 정책브리핑 운영 부서(문화체육관광부 국민소통실)에 사전 문의하는 편이 맞다. 연락처는 해당 기관 누리집에서 확인한다.

#### policy-kr-005 — KISTEP 발간물

| 항목 | 내용 |
|---|---|
| 접근 방식 | 목록 페이지 `kistep.re.kr/reportAllList.es?mid=a10305010000` (전체 연구보고서 1,181건) |
| 제공 정보 | 보고서명, 연구책임자·소속, 발행일, **KISTEP이 직접 부여한 키워드 태그**, 다운로드·미리보기 |
| 이용약관 위치 | **없음.** 목록 페이지·푸터·「홈페이지 운영지침」을 모두 확인했으나 저작권 안내, 이용약관, 공공누리 표시가 없다. 운영지침은 게시물 관리 절차만 다룬다 |
| 재배포 범위 | **허락 근거 없음.** 열람은 자유롭지만 재배포를 허락하는 표시가 없다 |
| PDF 텍스트 추출 | **가능.** 표본 4건 모두 텍스트 층과 `ToUnicode` 표가 있고 한글이 복원된다. 스캔본 0건 |
| 확인일·확인자 | 2026-10-17 접근 확인, 2026-10-18 PDF·이용조건 확인, B |
| 판정 | **`terms_ok_local`** (2026-10-18 결정) — 로컬 분석만. 공개 산출물에는 집계 수치와 제목·발행일·URL까지만 쓰고 본문은 싣지 않는다. 수집 경로(PDF)는 아직 구현하지 않았다 |

**PDF 표본 확인 결과 (2026-10-18, 이슈 #31)** 최근 보고서 4건을 내려받아 표준 라이브러리로 검사했다. 파일은 저장소에 넣지 않았다.

| 보고서 | 크기 | 쪽 | 텍스트 층 | 한글 복원 |
|---|---|---|---|---|
| 임무중심 혁신정책 관점의 정책-투자 분석 | 1.76 MB | 255 | 있음 (글꼴 285, ToUnicode 6) | 됨 |
| 고준위 방사성폐기물 지하연구시설 사업계획 적정성 검토 | 5.80 MB | 265 | 있음 (글꼴 372, ToUnicode 23) | 됨 |
| 국민체감진단 위탁연구 | 4.89 MB | 223 | 있음 (글꼴 341, ToUnicode 17) | 됨 |
| 인간-AI 협업형 LAM 개발·글로벌 실증 사업 | 4.70 MB | 244 | 있음 (글꼴 377, ToUnicode 27) | 됨 |

표본 4건에 스캔본은 없었다. 전체 1,181건의 비율은 이것으로 말할 수 없다. 오래된 보고서에는 스캔본이 있을 수 있으므로, 수집기를 만들면 스캔본을 `pdf_scan_unsupported` 로 기록하고 건너뛴다(기획안 §3, OCR은 범위 밖).

**내려받을 때 참조 주소가 필요하다.** `reportDownload.es` 를 바로 요청하면 403이 돌아오고, 목록 페이지를 `Referer` 로 보내면 200이다. 사람이 목록에서 누르는 것과 같은 조건이며, 로그인이나 접근 제한을 우회한 것이 아니다.

**KISTEP 부여 키워드** 목록 페이지 HTML의 `fncKeywordSplit('#키워드 #키워드 …')` 에 들어 있어 그대로 읽을 수 있다. 첫 쪽 10건 중 4~5건이 ICT 관련 키워드(`#인공지능`, `#피지컬AI`, `#AI 인프라`, `#로봇`, `#SW플랫폼`)를 달고 있다. 우리 사전 기반 추출 결과를 견줄 **독립된 기준**으로 쓸 수 있다(완료 기준 C5). 다만 KISTEP 키워드는 보고서의 정책 주제를 가리키므로 ICT 기술용어 사전과 범위가 다르다.

**참고할 점** KISTEP이 보고서마다 키워드를 달아 둔다(예: `#인공지능 #피지컬AI #사업계획 적정성 검토`). 우리 사전 기반 추출 결과를 **대조할 기준**으로 쓸 수 있다. 완료기준 C5(추출 품질 검토)에 활용할 만하다.

선별은 수집 단계에서 못박지 않았다. 기획안 §4가 기술용어 사전 기반 추출로 관련성을 판단하도록 정했고, 비ICT 제외 규칙은 아직 합의 전이다(`docs/topic_filter_rules.md`). 대신 수집기가 항목마다 목록에 적힌 분류(`Podcast`, `press-release` 등)를 실행 기록에 남기고, 필요하면 `--exclude-category` 로 걸러낼 수 있게 했다.

**과거 자료 수집 한계 (2026-10-17 확인, 이슈 #37)**

| 출처 | 과거 목록 | 확인 내용 |
|---|---|---|
| OSTP | 가능 | `?query-54-page=2` 로 넘어간다 |
| NSF | **불가** | 목록이 최신 9건만 준다. `?page=1` 을 줘도 같은 9건이고, 보관 목록(`/news/releases`)은 HTTP 202로 빈 문서가 온다 |
| DOE | **불가** | 뉴스룸이 최신 18건만 준다. 검색 목록은 `page=5` 를 줘도 `page=0` 과 같은 결과다(자료를 JS로 불러온다) |

NSF·DOE는 수집 기간 6개월을 한 번에 채울 수 없다. 뉴스 피드처럼 **주기적으로 실행해 쌓는다.** JS 실행이나 비공개 API로 대체 수집하지 않는다(§1 원칙). 수집기는 출처마다 `paging_supported` 를 실행 기록에 남겨, 최신 묶음만 받은 이유를 나중에 알 수 있게 한다.

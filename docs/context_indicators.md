# 맥락·확산 지표 설계 (대시보드 1단계 확장)

**상태: 설계안(미구현).** 집계(`aggregate.py`, #13)와 보고서(#19)가 B 담당이라 구현 전에 B와 합의가 필요하다. 기획안 §2 "포함" 범위를 넓히는 변경이므로 §8의 수정안도 함께 합의한다.

## 1. 해결하려는 문제

지금 대시보드는 "어떤 키워드가 몇 건 나왔는가"만 답한다. 실제 뉴스·정책 138건(2026-10-17 수집)에서 `인공지능`은 68건 검출됐지만, 숫자만으로는 **왜 많은지**, **무엇과 묶여 쓰이는지**, **한 매체가 몰아서 쓴 것인지**를 알 수 없다. 이 설계는 그 질문에 **지금 있는 데이터만으로** 답하는 지표를 더한다.

같은 데이터로 시험한 결과(참고, 정확도 평가가 아님):

| 질문 | 지표 | 현재 데이터에서 보인 것 |
|---|---|---|
| 무엇과 함께 쓰이나 | 함께 나온 키워드 | 인공지능과 같은 문서에 로봇 10건, 사이버보안 8건, AI 에이전트 7건, 클라우드 7건 |
| 한 곳이 몰아서 쓴 건가 | 출처 분해 | 인공지능 68건 = 전자신문 38, ZDNet 14, 긱뉴스 10, 보안뉴스 6 |
| 어떤 표기로 쓰였나 | 표기 분해 | `AI` / `인공지능` 비중 (`matched_terms`에 이미 있음) |
| 얼마나 퍼졌나 | 확산도 | 언급한 출처 수, 뉴스·정책 양쪽 등장 여부 |
| 한때인가 계속인가 | 지속성 | 연속으로 등장한 기간 수 |
| 이게 무슨 기술인가 | 키워드 설명·분류 | 사전에 설명과 분야 추가 |

## 2. 하지 않는 것: "영향도"라는 이름

기획안 §2는 "기술의 혁신성·성숙도·시장성이나 미래 유망성을 판정하지 않는다"고 한다. 언급량에서 실제 영향력을 읽을 수 없으므로 이 설계는 **영향도를 측정하지 않는다.** 대신 측정 가능한 대리 지표를 **확산도·지속성**이라는 이름으로 보여 준다. 화면과 보고서에는 다음 문구를 지표 옆에 둔다.

- 확산도: "몇 곳에서 언급됐는지를 뜻하며, 영향력이나 중요도를 뜻하지 않습니다."
- 함께 나온 키워드: "같은 문서에 나온 횟수이며, 인과나 연관 강도를 뜻하지 않습니다."
- 지속성: "연속해서 언급된 기간 수이며, 성숙도나 전망을 뜻하지 않습니다."

실제 영향(특허, 논문, 투자, 시장 규모)은 외부 데이터가 필요하고 기획안은 이를 후속 과제로 정했다. 이 설계도 그대로 둔다.

## 3. 지표 정의

모든 지표는 기존 지표와 **같은 기준**(중복 제거 후 분석 완료 문서, `published_date`, 한국 표준시, 일·주·월 기간, 뉴스/정책/통합 유형)을 쓴다. 통합(`all`)은 문서 ID 합집합으로 센다.

### 3-1. 함께 나온 키워드 (`keyword_context.csv`, 새 파일)

행 단위: **기간 × 자료 유형 × 키워드 × 함께 나온 키워드**

| 열 | 설명 |
|---|---|
| `period_type`, `period_start`, `period_end`, `source_type` | `keyword_stats.csv`와 같은 의미 |
| `keyword_id`, `keyword` | 기준 키워드 |
| `related_keyword_id`, `related_keyword` | 같은 문서에 함께 나온 다른 키워드 |
| `co_document_count` | 두 키워드를 모두 포함한 문서 수 |
| `co_share` | `co_document_count ÷ 기준 키워드의 document_count × 100`, 소수 둘째 자리 |
| `rank` | 같은 (기간, 유형, 기준 키워드) 안에서 `co_document_count` 내림차순, 동률은 공동 순위 |

- 두 방향(A→B, B→A)을 모두 행으로 만든다. `co_document_count`는 같고 `co_share`는 다르다.
- 함께 나온 문서가 0건인 쌍은 행을 만들지 않는다.
- `co_document_count ≥ 1`인 쌍 전부를 저장하고, 화면에서 상위 N개만 보여 준다.

### 3-2. 출처 분해 (`keyword_sources.csv`, 새 파일)

행 단위: **기간 × 자료 유형 × 키워드 × 출처**

| 열 | 설명 |
|---|---|
| `period_type`, `period_start`, `period_end`, `source_type` | 위와 같음 |
| `keyword_id`, `keyword` | 키워드 |
| `source_name` | `documents.csv`의 `source_name` |
| `document_count` | 그 출처에서 이 키워드를 포함한 문서 수 |
| `source_total_documents` | 그 출처의 해당 기간 분석 문서 수(분모, 키워드 없는 문서 포함) |
| `source_share` | `document_count ÷ source_total_documents × 100` |

출처 하나가 전체 빈도의 대부분을 차지하는지 볼 수 있다. 분모를 함께 두는 이유는 기사를 많이 내는 매체가 자동으로 커 보이는 것을 막기 위해서다.

### 3-3. 표기 분해 (`keyword_terms.csv`, 새 파일)

행 단위: **기간 × 자료 유형 × 키워드 × 실제 표기**

| 열 | 설명 |
|---|---|
| (기간·유형·키워드) | 위와 같음 |
| `term` | `matched_terms`에 있는 실제 표기(예: `AI`, `인공지능`) |
| `document_count` | 그 표기가 나온 문서 수 |

표기 하나가 두 문서에 걸쳐 나오면 두 문서를 센다. 표기별 출현 횟수는 `document_keywords.csv`에 표기별로 나뉘어 있지 않으므로 **문서 수만** 제공한다.

### 3-4. `keyword_stats.csv`에 추가하는 열 (선택 열, `is_partial_period`와 같은 방식)

| 열 | 정의 |
|---|---|
| `source_count` | 이 키워드가 나온 서로 다른 `source_name` 수 (해당 기간·유형) |
| `type_count` | 이 키워드가 나온 자료 유형 수(뉴스, 정책 중 몇 개). 통합 행에서만 의미 있음. 유형별 행은 `1` |
| `streak` | 이 기간을 포함해 **연속으로** 문서 빈도가 1 이상이었던 같은 단위(일·주·월) 기간 수 |

**`streak` 계산 규칙** 분석 문서가 **하나도 없는 기간은 건너뛴다**(끊지 않는다). 수집하지 않은 날을 "언급 없음"으로 보면 안 되기 때문이다. 분석 문서는 있었는데 그 키워드가 0건이면 연속이 끊긴다. 유형별(`news`/`policy`/`all`)로 따로 센다.

### 3-5. 키워드 설명·분류 (`config/keyword_meta.csv`, 새 설정 파일)

| 열 | 설명 |

| `description` | 한두 문장의 중립적 설명. 평가·전망 표현 금지 |

| `meta_version` | 메타 파일 버전. 사전 `dictionary_version`과 별개 |

## 4. 정답 예시 (고정 fixture 기준, 손으로 계산)

`tests/fixtures/`의 가상 데이터로 계산했다. 구현 코드의 출력을 복사하지 않았다. 문서별 키워드는 F001 {인공지능, 반도체}, F002 {인공지능}, F003 {인공지능, 생성형 AI}, F004 {클라우드}, F005 {양자컴퓨팅}, F008 {반도체, 정보기술}, F010 {인공지능, 반도체}이고 F006은 키워드 없음, F007은 중복 제외다.

**함께 나온 키워드** 월간 2026-09, 통합:

| 기준 | 함께 나온 | co_document_count | co_share |
|---|---|---|---|
| 인공지능 (4건) | 반도체 | 2 (F001, F010) | 50.00 |
| 인공지능 | 생성형 AI | 1 (F003) | 25.00 |
| 반도체 (2건) | 인공지능 | 2 | 100.00 |
| 생성형 AI (1건) | 인공지능 | 1 | 100.00 |

**지속성** 주간·뉴스 유형, 키워드 인공지능: 09-21주 문서 빈도 3 → `streak=1`. 09-28주는 뉴스 분석 문서가 2건(F005, F006) 있지만 인공지능이 0건이라 **행이 없고**, 이때 연속이 끊긴다. 10-05주는 뉴스 분석 문서가 없어 건너뛰므로(끊지 않음) 이후 주에 인공지능이 다시 나오면 `streak=1`부터 다시 센다. `streak`은 문서 빈도가 1 이상인 행에만 있다.

**출처 수** 월간 2026-09, 통합, 인공지능: fixture-news(F001, F002, F010)와 fixture-policy(F003) → `source_count=2`, `type_count=2`.

> 현재 fixture는 출처가 `fixture-news`, `fixture-policy` 둘뿐이라 `source_count`가 사실상 1~2로 단조롭다. 정답 검증용으로 `fixture-news-2` 출처의 가상 문서를 몇 건 추가하는 것이 필요하다. 추가하면 기존 정답 파일 전체를 다시 손으로 계산해 확인해야 하므로 별도 변경으로 진행한다.

## 5. 화면 구성 (대시보드)

키워드 순위의 한 줄을 누르면 지금은 근거 문서 목록만 펼쳐진다. 이를 **키워드 상세 패널**로 확장한다.

```
[ 인공지능 ]  분야: AI·모델   설명: (사전 설명 한두 문장)
 문서 68건 · 출처 4곳 · 뉴스·정책 · 연속 3주          ← 확산도·지속성(대리 지표 문구 포함)
 ┌ 근거 문서 │ 함께 나온 키워드 │ 출처 │ 표기 ┐
 │ (탭)                                       │
 │ 함께 나온 키워드: 로봇 10건(14.7%) 사이버보안 8건(11.8%) AI 에이전트 7건 …
 │ 출처: 전자신문 AI·SW 38건 (분석 문서 중 76.0%) / ZDNet Korea 14건 …
 │ 표기: 인공지능 41건 / AI 33건
 └─────────────────────────────────────────────┘
```

- 순위 목록에는 `출처 N곳`, `연속 M기간` 칩을 더해, 건수는 같은데 성격이 다른 키워드를 구분하게 한다.
- 분야는 필터로 쓸 수 있게 하되 1단계에서는 선택한 분야의 키워드만 보여 주는 정도로 한정한다.
- `local_only_no_publish` 출처는 출처 분해에서 **출처 이름은 보여 주되 제목은 숨긴다**(기존 규칙 유지).
- 모든 지표는 **통합·뉴스·정책과 일간·주간·월간 전환에 따라** 바뀐다. 한 유형에 자료가 없는 기간은 기존처럼 안내를 표시한다.

## 6. 2단계 이후 (이번 설계에서 제외)

| 항목 | 이유 |
|---|---|
| 문장 발췌(키워드 앞뒤 한 줄) | 본문이 필요하고 재배포 제한이 있다. 로컬 대시보드에서만 가능하며 `local_only_no_publish`는 숨겨야 한다. CSV로 전달하지 않는다 |
| 뉴스·정책 선후 관계 | "정책에 먼저 나온 날 – 뉴스에 처음 나온 날". 인과가 아님을 명시해야 하고, 두 유형의 공통 범위(`docs/period_policy.md`)에서만 해석 가능 |
| 분야 단위 집계 | 합집합 규칙과 fixture 정답이 추가로 필요 |
| 사건 단위 묶음 | 같은 사건을 다룬 기사를 하나로 보는 기능. 기획안 §4가 유사 기사 판별을 후속 과제로 둠 |
| 외부 영향 데이터 | 특허·논문·투자 연계는 후속 과제 |
| LLM 맥락 요약 | 재현성(C8)이 깨지고 본문을 외부로 보내게 된다. 쓴다면 집계 수치를 채우는 규칙 기반 문장만 |

3~6은 서로 의존이 적어 병렬로 진행할 수 있다. 1이 합의되기 전에는 4와 7을 시작하지 않는다.

## 8. 기획안 수정안 (합의 후 반영)

- §2 포함: "근거 문서 조회" 뒤에 "키워드의 함께 나온 키워드·출처 분포·확산도·지속성 표시(영향력·중요도 판정은 하지 않음)"를 추가한다. 후속 과제의 "연구동향 데이터 연계"는 그대로 둔다.
- §4 지표 정의: 확산도(`source_count`, `type_count`)와 지속성(`streak`)의 정의를 추가한다.
- §5 대시보드: "키워드를 선택하면 근거 문서를 조회한다"를 "…와 함께 나온 키워드, 출처 분포, 설명을 조회한다"로 확장한다. 분야 필터는 선택 사항으로 둔다.
- §6 CSV: `keyword_context.csv`, `keyword_sources.csv`, `keyword_terms.csv`를 추가 파일로, `config/keyword_meta.csv`를 설정으로 명시한다. **필수 3종 CSV의 구성은 바꾸지 않는다.**
- §10: 완료 기준 **C11**을 추가한다. "맥락·확산 지표가 정답 fixture와 정확히 일치하고 화면·보고서 수치가 같다."

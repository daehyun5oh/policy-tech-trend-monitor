# 추출·집계 규칙 (이슈 #5)

기획안 §4의 처리·지표 기준을 코드가 실제로 하는 동작에 맞춰 구체화한 문서다. 매칭 규칙은 `src/extract_keywords.py`, CSV 일관성 검사는 `src/validate_csv.py`에 구현되어 있다. 6장의 항목은 기획안에 없어서 A가 임시로 정한 값이므로 B와 확정해야 한다. 확정되면 `src/schema.py`와 `docs/data_dictionary.md`를 함께 고친다.

## 1. 분석 대상과 텍스트

- `status`가 `analyzed`인 문서만 분석한다. 제외·실패 문서는 키워드를 추출하지 않는다.
- `analysis_scope`에 따라 분석하는 텍스트가 정해진다.
  - `title`: 제목만
  - `title_summary`, `title_body`: 제목과 `<text-dir>/<document_id>.txt`
- 제목과 본문은 따로 매칭한 뒤 합친다. 제목 끝과 본문 첫머리가 이어져 만들어지는 일치는 인정하지 않는다.
- 본문 파일을 읽을 수 없으면 그 문서는 결과 없이 처리 실패로 보고하고, 실행은 종료 코드 2로 끝난다. 다른 문서의 결과는 그대로 기록한다.
- `document_id`를 파일 이름으로 쓰므로, 요약·본문 범위 문서의 `document_id`는 영문·숫자로 시작하고 영문·숫자·`_`·`.`·`-`만 써야 한다. 그 밖의 값은 파일 시스템에 접근하지 않고 오류로 처리한다.

## 2. 텍스트 정규화

매칭 전에 사전의 용어와 분석 텍스트를 같은 방식으로 정규화한다.

1. 유니코드 NFKC 정규화 (예: 전각 `ＡＩ` → `AI`)
2. 연속 공백·줄바꿈을 공백 하나로 합치고 앞뒤 공백 제거

`matched_terms`에는 정규화 이후의 표기가 기록된다. 대소문자는 정규화하지 않고 용어별 옵션(`case_sensitive`)으로 다룬다.

## 3. 매칭 규칙

| 규칙 | 내용 | 예 |
| --- | --- | --- |
| 표준 키워드 | 사전의 모든 표기(`term`)가 하나의 표준 키워드로 모인다 | `AI`, `인공지능` → 인공지능 |
| 대소문자 | `case_sensitive=1`인 용어만 대소문자를 구분한다. 짧은 약어는 1로 둔다 | `IT`는 `it`과 일치하지 않음 |
| 영문·숫자 경계 | 용어가 영문·숫자로 시작하면 바로 앞에, 끝나면 바로 뒤에 영문·숫자가 붙은 경우 일치하지 않는다. 한글이 붙은 경우는 일치한다 | `AI`는 `MAIL`, `AIR`, `AI2`와 불일치, `AI와`, `AI-powered`와 일치 |
| 복수형 | 영문 글자로 끝나는 용어 뒤의 소문자 `s` 하나를 허용한다 | `LLMs`, `GPUs` 일치, 대소문자 구분 용어 `AI`는 `AIS`와 불일치 |
| 한글 용어 | 경계를 검사하지 않는 부분 문자열 일치다. 조사가 붙어도 일치하지만 더 긴 낱말 안에서도 일치한다 | `반도체를` 일치 |
| 띄어쓰기 | 사전에 적힌 표기와 같을 때만 일치한다. 띄어쓴 표기와 붙인 표기는 둘 다 등록한다 | `양자컴퓨팅`, `양자 컴퓨팅` |
| 복합어 | 겹치는 후보 중 긴 것을 먼저 고르고, 같은 길이면 앞선 위치, 그다음 `keyword_id` 순으로 고른다. 고른 구간과 겹치는 짧은 후보는 버린다 | `생성형 AI` → 생성형 AI 1건, 인공지능 0건 |

복합어 규칙의 결과를 예로 들면 다음과 같다.

- `생성형 AI 활용 지침과 AI 윤리` → 생성형 AI 1회, 인공지능 1회 (뒤의 `AI`만 인공지능으로 센다)
- 현재 복합어 키워드는 생성형 AI, AI 에이전트, AI 반도체, 피지컬 AI, 소버린 AI, 온디바이스 AI다. 이 표기가 나온 문서에서는 안에 든 `AI`와 `반도체`가 따로 세어지지 않으므로, 이 키워드가 많을수록 인공지능·반도체 문서 빈도는 낮게 나온다.

한 문서·한 키워드에 대한 결과는 다음과 같다.

- `occurrences`: 선택된 일치 구간의 수
- `matched_terms`: 실제로 일치한 표기(정규화 후)를 중복 없이 모은 JSON 배열. 제목, 본문 순서이고 조각 안에서는 등장 순서다.
- 출력 행은 `document_id`, `keyword_id` 순으로 정렬한다. 같은 입력이면 항상 같은 파일이 나온다.

## 4. 사전 규칙 (`config/keywords.csv`)

- 열: `keyword_id`, `keyword`, `term`, `case_sensitive`, `dictionary_version`
- 모든 행의 `dictionary_version`은 같은 값이어야 한다.
- 표준 키워드(`keyword`) 자신도 `term`으로 등록해야 한다.
- 같은 `term`(대소문자 무시)이 서로 다른 `keyword_id`에 등록되어 있으면 오류다.
- 사전을 고치면 `dictionary_version`을 올리고 `document_keywords.csv`를 전부 다시 만든다. 한 파일에 서로 다른 버전이 섞이면 검증기가 오류로 처리한다.
- 뜻이 여러 개인 용어와 약어는 문서 목적에 맞는 쪽만 등록하거나 대소문자·경계로 범위를 좁힌다. 오탐이 확인된 용어는 고치고 `docs/dictionary_v1.md`에 기록한다.

## 5. 집계 지표 (기획안 §4 구체화)

| 항목 | 정의 |
| --- | --- |
| 기간 | 일간은 하루, 주간은 월요일~일요일, 월간은 달력 월. 한국 표준시, 시작일·종료일 포함. 기준은 `published_date`이고 날짜만 있는 자료에 시각을 붙이지 않는다 |
| 분모 | 해당 기간·유형에서 `status=analyzed`이고 발행일이 있는 모든 문서. 키워드가 하나도 없는 문서도 포함한다. 중복 제외·날짜 없음·실패 문서는 제외한다 |
| 문서 빈도 | 키워드를 포함한 분모 문서 수. 한 문서에서 여러 번 나와도 1건 |
| 출현 횟수 | 그 문서들의 `occurrences` 합 |
| 문서 비율 | 문서 빈도 ÷ 분모 × 100, 소수 둘째 자리 표기. 검증은 0.01 오차를 허용한다 |
| 순위 | 문서 빈도 내림차순. 동률은 공동 순위이고 다음 순위는 건너뛴다 (1, 1, 3). 같은 순위 안의 표시 순서는 키워드 이름의 문자열 순서다 |
| 분모 0 | 비율과 순위를 `해당 없음`으로 표시한다 |
| 통합(`all`) | 문서는 `source_type`을 하나만 가지므로 통합 분모는 뉴스 분모와 정책 분모의 합이고, 키워드별 통합 문서 빈도는 `max(뉴스, 정책)` 이상 `뉴스+정책` 이하다. 검증기가 이 관계를 검사한다 |
| 부분 기간 | 수집 종료일(집계 실행일)이 기간 안에 있거나 기간이 그 뒤까지 이어지는 기간. 집계가 `keyword_stats.csv`의 `is_partial_period`(`yes`/`no`)에 기록하고, 대시보드는 그 열이 있으면 그 값을 쓴다. 열이 없을 때만 `documents.csv`의 `collected_at` 최댓값으로 직접 판정한다 |

## 6. A·B가 확정한 항목

기획안에 값이 정해져 있지 않아 처음에는 A가 임시로 정했고, B의 데이터 사전(`docs/data_dictionary.md`)과 B의 집계 구현을 거쳐 아래와 같이 맞췄다.

| 항목 | 확정 값 | 정의된 곳 | 결과 |
| --- | --- | --- | --- |
| `status` 저장 값 | `analyzed`, `excluded`, `failed` | `src/schema.py`, 데이터 사전 | 같음 |
| `analysis_scope` 저장 값 | `title`, `title_summary`, `title_body` | `src/schema.py` | **B의 데이터 사전을 따라 A의 값(`summary`, `body`)을 바꿈** |
| `period_type` 저장 값 | `daily`, `weekly`, `monthly` | `src/schema.py` | 일간 추가(대시보드 요청). B 집계가 같은 값을 만듦(PR #46, 머지 전) |
| 동률 순위 방식 | 공동 순위 후 건너뜀 (1, 1, 3) | `src/validate_csv.py`, B의 `aggregate.py` | 같은 규칙(B는 "경쟁 순위 1, 2, 2, 4"로 표현). 같은 fixture에서 값이 모두 일치 |
| 문서 비율 표기 | 소수 둘째 자리 | fixture, 검증기, B의 집계 | 같음 |
| 요약·본문 텍스트 전달 | `<document_id>.txt`. 폴더는 정책 `data/raw`, 뉴스 `data/processed/texts` (추출기가 차례로 찾음) | `src/extract_keywords.py` | 정책 수집기의 폴더에 맞춤(PR #39) |
| `keyword_stats.csv` 행 | 문서 빈도 1 이상인 키워드만 행을 둔다. 분모 0 기간은 행을 만들지 않고 실행 기록에만 문서 수를 남긴다 | fixture, 검증기, B의 집계 | 같음 |
| 부분 기간 판정 | 수집 종료일이 기간 안이거나 기간이 그 뒤까지 이어질 때. 열 `is_partial_period`가 있으면 그 값 우선 | B의 집계, `dashboard/app.py` | **B가 열을 만들고 대시보드가 그것을 읽도록 맞춤** |
| `exclusion_reason` 값 | 데이터 사전 §3의 허용값. 검증기는 제외·실패 문서에 값이 비어 있지 않은지만 본다 | 데이터 사전, `src/validate_csv.py` | 허용값 검사는 후속 과제 |

## 7. 알려진 한계

- 한글 용어는 부분 문자열로 일치하므로 한글 표기 제품명이나 더 긴 낱말 안의 용어가 키워드로 잡힌다.
- 영문 일반명사가 제품명으로 쓰인 경우를 구별하지 못한다. 실제 샘플에서 `Cloud in a Bottle`의 `Cloud`가 클라우드로 집계되었다.
- 집계값은 언급량이다. 정치·사회 맥락에서 쓰인 용어(예: 오픈소스를 다룬 정치 글)도 같은 키워드로 센다.
- 어미·활용 변형은 처리하지 않는다. 사전에 없는 용어는 결과에 나타나지 않는다.
- 유사 기사 판별은 후속 과제다 (기획안 §4-3).

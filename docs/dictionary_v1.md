# 키워드 사전 v1 (이슈 #10)

`config/keywords.csv`의 v1 초안과 선정 근거를 적은 문서다. 이 사전은 정책 자료로 검증하지 않은 **초안**이다. 정책 쪽 용어는 근거 자료 없이 넣었으므로 B의 검토가 필요하다.

## 1. 구성

- 표준 키워드 47개, 표기(`term`) 170개, 그중 대소문자를 구분하는 표기 17개
- 형식과 적용 규칙은 `docs/extraction_rules.md` 3~4장에 있다.
- 복합어 키워드는 6개다: 생성형 AI, AI 에이전트, AI 반도체, 피지컬 AI, 소버린 AI, 온디바이스 AI. 이 표기가 나온 문서에서는 안에 든 `AI`·`반도체`가 인공지능·반도체로 따로 세어지지 않는다.
- `확장현실` 키워드는 XR, VR, AR(대소문자 구분)과 가상현실, 증강현실을 하나로 묶는다. 구분이 필요하면 키워드를 나눠야 한다.

## 2. 선정 근거와 한계

**뉴스 쪽 근거 (부분적).** 긱뉴스 제목 1,417건 목록(공개 저장소를 정리하며 삭제한 샘플)에 이 사전을 적용했다. 제목만 분석했고, 샘플을 `documents.csv` 형식으로 바꿀 때 중복 제거는 하지 않았다 (2026-10-17 측정).

- 1건 이상 검출된 문서: 303건 (21.4%)
- 검출된 키워드: 47개 중 22개, 한 번도 검출되지 않은 키워드: 25개
- 이 샘플은 개발자 커뮤니티의 뉴스 목록이어서, 기획안이 대상으로 하는 디지털·ICT 정책 뉴스의 대표 표본이라고 볼 수 없다.

**정책 쪽 근거 (없음).** 디지털플랫폼정부, 마이데이터, 소버린 AI, 디지털 전환, 스마트시티처럼 정책 문서에서 쓰일 법한 용어는 작성자의 일반 지식으로 넣었다. 실제 정책 문서에 적용해 확인한 적이 없다. 샘플에서 0건인 것은 오류가 아니라 샘플의 성격 때문일 가능성이 높지만, 이것도 확인된 것은 아니다.

**선정 기준.** 디지털·ICT 분야를 넓게 덮도록 만든 목록이며, 객관적인 선정 기준(빈도 순위, 공식 분류 등)을 적용한 것은 아니다.

## 4. 확인된 문제와 판단이 필요한 점

- **영문 제품명 오탐:** `Cloud in a Bottle`의 `Cloud`가 클라우드로 집계되었다. 영문 일반명사가 제품명으로 쓰인 경우는 구별하지 못한다.
- **맥락 무관 집계:** 오픈소스를 정치 맥락에서 다룬 글도 오픈소스 키워드로 집계되었다. 이 수치는 기술 동향이 아니라 언급량이다.
- **복합어의 영향:** AI 에이전트(20건) 등 복합어 키워드가 있어서 해당 문서에서는 `AI`가 인공지능으로 세어지지 않는다. 인공지능 176건에는 복합어 안에 든 `AI`가 포함되어 있지 않다.
- **판단 사례:** `NPU` 단독 표기가 AI 반도체로 집계되었다. 타당하다고 보고 넣었지만 합의된 분류는 아니다.
- **누락 용어:** 샘플에 나오지만 사전에 없는 용어는 체계적으로 조사하지 않았다. 제품·서비스 이름(예: Claude Code)은 넣지 않았고, 넣을지는 결정되지 않았다.

## 5. 검토 요청

- [ ] 정책 용어를 실제 정책 문서(B의 출처)에 적용해 추가·삭제할 용어를 확정한다.
- [ ] 샘플에서 0건인 25개 키워드를 유지할지 정한다.
- [ ] 대소문자를 구분하는 17개 표기가 의도와 맞는지 본다.
- [ ] 복합어 6개를 유지할지, 구성어도 함께 세는 방식으로 바꿀지 정한다 (`docs/extraction_rules.md` 3장).
- [ ] `확장현실`을 XR·VR·AR로 나눌지 정한다.

## 6. 변경 절차

1. `config/keywords.csv`를 고치고 모든 행의 `dictionary_version`을 올린다 (예: `v1` → `v2`).
2. `python -m unittest discover -s tests`로 사전이 규칙에 맞는지 확인한다. 사전 자체의 검사는 `load_dictionary`가 실행 때마다 한다.
3. `document_keywords.csv`를 전부 다시 만든다. 한 파일에 서로 다른 버전이 섞이면 `src/validate_csv.py`가 오류로 처리한다.
4. 바꾼 내용과 이유를 이 문서에 기록한다.

## 7. 재현 방법

샘플을 `documents.csv` 형식으로 바꾸는 코드는 레포에 없다 (B의 #4, #9 범위). 위 수치는 다음 대응으로 바꾼 뒤 `python src/extract_keywords.py`를 실행한 결과다.

| `documents.csv` 열 | 값 |
| --- | --- |
| `document_id` | `G` + 4자리 순번 |
| `source_type`, `source_name` | `news`, `geeknews` |
| `source_document_id`, `original_url` | 샘플의 `url` |
| `title`, `published_date` | 샘플의 `title`, `date` |
| `analysis_scope`, `status` | `title`, `analyzed` |

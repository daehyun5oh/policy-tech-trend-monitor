# 대시보드 사용 가이드

시연 영상을 만들거나 처음 쓰는 사람이 화면을 이해하도록 쓴 설명서다. 화면에 나오는 이름 그대로 적었다. 계산 정의는 `docs/insight_views.md`, 키워드 사전은 `docs/dictionary_v3.md`에 있다.

> **먼저 알아둘 것.** 이 화면의 숫자는 **언급량**이다. "그 키워드가 나온 문서가 몇 건인가"이며 기술의 중요도나 전망을 뜻하지 않는다. 화면 어디에도 "급증", "유망" 같은 판정을 쓰지 않는다.

## 1. 어떤 도구인가

- 뉴스(RSS)와 정책 자료(과기정통부 RSS, 미국·중국 기관 목록 페이지)에서 문서를 모으고, 미리 정한 **키워드 사전**(49개 키워드)에 있는 표기가 나온 문서를 센다.
- 결과는 **내 컴퓨터에 만들어지는 HTML 파일 한 개**다. 서버가 없고, 수집한 자료는 저장소에 올라가지 않는다.
- 공개 데모(합성 데이터): https://hyeon0.github.io/tech-trend-keyword-monitor/ — 제목·출처·숫자를 모두 지어낸 자료다.

## 2. 실행 방법

```bash
python setup_env.py     # 처음 한 번. 정책 수집용 패키지를 저장소 안 .venv 에 설치 (뉴스만 볼 때는 생략 가능)
python monitor.py       # 시작일·종료일을 물어본다. 그냥 Enter 면 최근 7일
```

- 입력한 기간의 뉴스·정책을 모으고 대시보드를 브라우저로 연다. 바로 지정하려면 `python monitor.py --from 2026-10-14 --to 2026-10-21`.
- 끝나면 **요청한 기간과 실제 확보한 기간**을 나란히 알려 준다. 뉴스 피드는 최근 기사만 주므로(ZDNet 약 15시간, 긱뉴스 약 하루, 전자신문 약 이틀, 보안뉴스 약 4주) 먼 과거는 비어 있을 수 있다. 며칠 간격으로 다시 실행하면 받는 기간이 늘어난다.
- 받은 자료는 임시 폴더(`%TEMP%\policy-tech-trend-monitor`)에 쌓이고, 실행할 때마다 발행일이 90일 지난 자료가 지워진다. 비우려면 `python monitor.py --clean`.
- 만들어진 대시보드에는 기사·문서 **제목과 링크가 들어 있으니 다른 사람에게 보내지 않는다.** 시연 영상에는 공개 데모나 직접 수집한 화면을 쓰되, 국무원·중국과학원 제목은 화면에 나오지 않는다(비공개 규칙).

## 3. 화면 구성

위에서 아래로 한 번에 읽도록 카드를 배치했다. 긴 설명은 제목 옆 **`?`**를 누르면 나온다.

### 맨 위: 조회 조건 (한 줄)

| 항목 | 선택지 | 뜻 |
|---|---|---|
| 기간 단위 | **조회 기간 전체** / 일간 / 주간 / 월간 | 처음에는 입력한 기간 전체를 한 번에 요약한다. 일간·주간·월간으로 바꾸면 기간을 나눠 보고 "평소와 비교"가 나온다 |
| 기간 | 선택 | 선택한 단위의 기간 |
| 자료 유형 | 통합 / 뉴스 / 정책 | 통합은 뉴스와 정책을 합쳐서(같은 문서를 두 번 세지 않는다) 본다 |
| 순위에 보일 키워드 | 상위 5·10·20·50개 | 순위 카드에 보이는 개수 |

조건 아래 작은 글씨에 뉴스·정책 자료의 날짜 범위, 수집 종료일, 화면 생성 시각이 나온다. 부분 기간이나 자료 범위 차이 같은 알림은 **칩 한 줄**과 접힌 "안내 N건 보기"에 모았다.

### 카드 목록

| 카드 | 보이는 것 | 읽는 법 |
|---|---|---|
| **한눈에 보기** | 타일 4개와 한 문장 요약 | ① 분석한 문서 수(통합이면 뉴스·정책 비율 막대) ② 검출된 키워드 수와 1위 ③ 조회 기간 전체에서는 "실제 확보한 자료 기간", 일간·주간·월간에서는 "평소보다 비중이 커진 키워드" 수 ④ 정책 문서의 나라 수(뉴스를 고르면 뉴스 출처 수) |
| **많이 언급된 키워드** | 순위와 막대 | 막대는 문서 빈도(그 키워드가 나온 문서 수). 같은 값은 **공동 순위**. 키워드를 누르면 **근거 문서**, **함께 나온 키워드**, **출처**, **표기** 탭이 열린다 |
| **자료 구성** | 출처별 분석 문서 수 막대 | 뉴스는 파랑, 정책은 주황. 출처마다 문서 수와 분석 범위(제목만/요약/본문)가 달라 출처끼리 그대로 견주면 한쪽에 치우친다 |
| **정책: 국가별 키워드** (통합·정책) | 한국·미국·중국 칸마다 키워드 막대 | 막대는 **그 나라 정책 문서 중 키워드가 나온 문서의 비중(%)**이라 문서 수가 다른 나라끼리 견줄 수 있다. "표로 보기"에 키워드×나라 표가 있다 |
| **정책 문서** (정책 선택 시) | 날짜순 문서 목록 | 국가 칩으로 거르고, 문서마다 검출된 키워드를 칩으로 보인다. "사전 키워드 없음"이 많으면 그 문서들이 ICT 주제가 아닌 경우가 많다 |
| **평소와 달라진 키워드** (일간·주간·월간) | 점 두 개짜리(덤벨) 차트 | 회색 점은 **평소**(바로 앞 기간들의 문서 비중), 파란 점은 **이번 기간**. 뱃지 **뚜렷함**은 차이가 우연한 변동과 구별될 만큼 크고 건수가 5건 이상, **참고용**은 그 밖. 중요도를 뜻하지 않는다. **상시** 태그는 전체의 40% 이상 문서에 나오는 키워드 |
| **흐름** | 키워드별 작은 꺾은선 | 조회 기간 전체에서는 일별. 선이 끊긴 곳은 그날 분석 문서가 없다는 뜻 |
| **뉴스와 정책은 어떻게 다른가** (통합) | 왼쪽 뉴스, 오른쪽 정책 막대 | 같은 눈금의 문서 비중. "뉴스에만"·"정책에만" 태그. 뉴스와 정책이 각각 5건 이상 있어야 나온다 |
| **분야 안에서 보기** | 분야 칩과 덤벨/막대 | 분야(AI·모델, 보안·개인정보 등)를 고르면 그 분야 문서 안에서의 비중 |

모든 차트에는 **"표로 보기"**가 있어 건수와 표준화 점수까지 볼 수 있다.

## 4. 화면이 비어 보일 때

| 증상 | 이유 |
|---|---|
| "비교 불가" | 직전 기간의 분석 문서가 20건 미만이거나 이번 기간이 5건 미만. 조회 기간 전체에서는 비교 대상(직전 기간)이 없다 |
| 정책 키워드가 적다 | 정책 출처에는 시상식·환경 규정처럼 ICT가 아닌 문서가 많다(`docs/dictionary_v3.md` §3). 사전은 ICT 용어만 센다 |
| 뉴스가 일부 날짜만 있다 | 뉴스 피드는 최근 기사만 준다. 요청 기간과 실제 확보 기간은 실행 끝에 나온다 |
| 중국 문서 제목이 안 보인다 | 국무원·중국과학원은 재배포 제한(`local_only_no_publish`)이라 제목·본문을 싣지 않고 URL·날짜만 쓴다 |
| 정책 수집이 빠졌다 | 외부 패키지가 없다. `python setup_env.py` 후 다시 실행한다 |

## 5. 시연 영상에서 보여 주면 좋은 순서 (제안)

1. 공개 데모(또는 직접 수집한 화면)를 열고 "언급량을 세는 도구이며 중요도를 판정하지 않는다"고 말한다
2. 조회 조건 → **한눈에 보기** 타일과 한 문장 요약
3. **많이 언급된 키워드**에서 키워드 하나를 눌러 근거 문서와 함께 나온 키워드를 보여 준다(숫자의 근거를 확인할 수 있다는 점)
4. **자료 구성**과 **정책: 국가별 키워드**로 한국·미국·중국 차이, 정책을 고르면 **정책 문서** 목록
5. 기간 단위를 **주간**으로 바꿔 **평소와 달라진 키워드**(뚜렷함/참고용)와 **뉴스와 정책은 어떻게 다른가**
6. `?`와 "표로 보기"를 한 번씩 눌러 보이고, 한계(뉴스 피드 기간, 사전 기반, 정확도 미측정)를 짚는다
7. 터미널에서 `python monitor.py`로 실제 수집이 도는 모습(요청 기간 대비 확보 기간 안내)

## 6. 한계

- 빈도는 언급량이다. 같은 사건을 여러 곳이 다루면 여러 번 센다.
- 사전에 있는 표기만 센다. 사전에 없는 용어는 놓치고, 스쳐 가는 언급도 센다. 정확도·재현율은 측정하지 않았다.
- 뉴스는 피드가 주는 최근 기사만, 정책은 출처마다 최근 N건만 받는다. 자료가 쌓일수록 비교가 의미를 갖는다.

# 시연 영상 대본

영상은 두 개다. **README용**(짧게, 승인 PR용)과 **LMS 제출용**(중간 과제, 고도화 전/후). **시연은 합성 데모가 아니라 실제 도구를 직접 쓰는 모습**으로 한다: 터미널에서 `python monitor.py`를 실행해 실제 뉴스·정책을 수집하고, 그 결과로 만들어진 대시보드를 보여 준다. 공개 데모(합성 샘플)는 **배포 주소가 열리는 것을 보여 줄 때만** 쓴다.

- 공개 데모(배포 주소, 합성 샘플): https://hyeon0.github.io/policy-tech-trend-monitor/
- 실제 시연: 이 도구를 설치한 PC에서 `python monitor.py`
- 비교 링크: README 맨 위
- **화면에 나와도 되는 것과 안 되는 것**: 실제 대시보드에는 뉴스·정책 문서의 제목과 링크가 보이지만, 뉴스 4곳과 한국·미국 정책 출처는 제목·URL·발행일을 공개할 수 있는 범위(`metadata_only` 등)다. **국무원·중국과학원 제목은 대시보드가 자동으로 가려 준다**(`(제목 비공개)`). 그래도 영상에서 문서 본문을 읽거나 길게 클릭해 넘기지 않는다.

## 녹화 전 준비

1. 다른 창·알림을 끈다. 터미널 경로에 사용자 이름이 보이면 `cd`로 짧은 폴더로 옮기거나 프롬프트를 지운다
2. 브라우저는 시크릿 창으로 연다(북마크·계정 표시가 안 보이게). 실제 대시보드는 `file:///C:/Users/<이름>/...` 주소로 열려 **주소창에 사용자 이름이 보이므로 F11(전체 화면)로 주소창을 가린다**
3. PowerShell 프롬프트에도 경로(사용자 이름)가 보인다. 녹화 전에 `function prompt { "PS> " }` 를 입력해 프롬프트를 짧게 바꾼다. 글자는 크게 한다
4. 수집을 한 번 미리 돌려 정책 패키지가 설치돼 있는지 확인한다(`python setup_env.py --check`). 실제 수집은 **약 1분**(정책 포함, 기간을 짧게 줄 때) 걸리므로 그동안 설명을 이어서 말한다
5. 합성 데모를 열 때는 "샘플 데이터 데모" 띠가 위에 보인다. 그대로 두고 "배포용으로 지어낸 자료"라고 말한다

## A. README용 영상 (30초 안팎, 10MB 이하)

| 시간 | 말 | 화면 |
|---|---|---|
| 0:00 | 뉴스와 정책에서 기술 키워드가 몇 건의 문서에 나왔는지 세는 도구입니다. 기간을 입력하면 직접 수집합니다. | 터미널: `python monitor.py --from 2026-10-15 --to 2026-10-22` 입력 직후(실제 수집은 미리 해 둔 결과를 열어 보인다고 말한다) |
| 0:08 | 방금 이 도구로 수집한 실제 자료입니다. 한눈에 보기에서 문서 수와 키워드를 보여 줍니다. | 실제 대시보드, 한눈에 보기 |
| 0:15 | 키워드를 누르면 그 숫자의 근거 문서가 열립니다. | 많이 언급된 키워드 → 1위 클릭 |
| 0:21 | 정책은 나라별로 나눠 키워드를 비교합니다. | 자료 유형 → 정책 → 국가별 키워드 |
| 0:27 | 이 숫자는 언급량이며 중요도가 아닙니다. | 맨 위 안내 |

> 30초에는 실제 수집(약 1분)이 들어가지 않는다. 그래서 README용 영상은 **수집을 미리 끝낸 상태에서** 명령 입력 장면과 결과 화면을 보여 주고, 수집 과정은 아래 LMS용 영상에서 끝까지 보여 준다.

녹화 방법은 슬라이드 50쪽: 화면 기록(Windows는 Win+Alt+R 또는 Win+G) → 영상 파일 → README 편집 화면에 끌어 놓기 → **새 브랜치로 PR** → 상대가 재생·승인·병합.

## B. 제출용 설명 영상 (개인, 5분 이내)

과제 안내가 요구하는 다섯 가지를 **이 순서대로** 담는다. 같은 도구라도 활용 방식(use case)은 사람마다 다르므로, **[ ]로 표시한 곳은 본인의 연구·관심 주제와 경험으로 바꿔 말한다.**

| # | 담을 것 | 시간 |
|---|---|---|
| 1 | 왜 만들었나(어떤 일을 하면서 무엇이 필요했나) | 0:00 ~ 0:45 |
| 2 | 어떻게 쓰나(입력 → 결과를 화면으로) | 0:45 ~ 2:15 |
| 3 | 내 연구·관심 주제에는 어떻게 쓸 수 있나 | 2:15 ~ 3:15 |
| 4 | 내가 고친 부분 | 3:15 ~ 4:00 |
| 5 | 써 보니 아쉬운 점 | 4:00 ~ 4:45 |

### 1. 왜 만들었나 (0:00 ~ 0:45)
- "[저는 정책 연구를 준비하면서] 요즘 어떤 기술이 뉴스와 정부 정책에서 많이 언급되는지 알아야 했습니다."
- "기사와 정책 문서가 여러 곳에 흩어져 있어서 하나씩 읽어 파악하기에는 시간이 오래 걸렸고, 그 숫자가 어디서 나왔는지 근거를 확인하기도 어려웠습니다."
- "그래서 **뉴스와 정책에서 기술 키워드가 몇 건의 문서에 언급됐는지 세고, 근거 문서까지 보여 주는 도구**를 만들었습니다. 언급량을 보여 줄 뿐 기술의 중요도나 전망을 판정하지 않습니다."
- (공개 데모 화면) "이 화면은 배포용으로 지어낸 샘플 데이터로 만든 데모입니다."

### 2. 어떻게 쓰나 — 입력에서 결과까지 (0:45 ~ 2:15)
- (터미널) "입력은 세 가지입니다. 조회할 **기간**, 수집할 **출처 목록**(`config/sources.csv`), 그리고 키워드 **사전**(`config/keywords.csv`)입니다."
- "`python monitor.py`를 입력하면 기간을 묻고, 기간을 정하면 뉴스 네 곳과 정책 출처를 수집합니다. 출처마다 요청은 한 번씩만 보냅니다."
- (수집이 도는 동안 수집 단계 줄을 가리키며) "수집 → 키워드 찾기 → 집계 → 검증 → 대시보드 순서로 진행됩니다."
- (끝난 뒤) "끝나면 요청한 기간과 실제로 확보한 기간을 알려 줍니다. 뉴스 피드는 최근 기사만 주기 때문에 먼 과거는 비어 있을 수 있습니다."
- (브라우저에서 실제 대시보드, 한눈에 보기) "결과 화면입니다. 분석한 문서 수, 뉴스와 정책 비율, 키워드 수와 1위를 보여 줍니다."
- (키워드 클릭) "키워드를 누르면 근거가 된 문서를 볼 수 있습니다. 숫자가 어디서 나왔는지 확인되는 점이 이 도구의 핵심입니다."

### 3. 내 연구·관심 주제에 쓰면 (2:15 ~ 3:15)
- "[제 관심 주제는 ______(예: 인공지능 에이전트와 AI 거버넌스)입니다.] 이 도구로 그 키워드가 뉴스와 정책에서 얼마나, 어떻게 나오는지 봅니다."
- (자료 유형을 통합 → 뉴스 → 정책으로) "같은 키워드가 뉴스에서는 많은데 정책 문서에서는 적은지, 반대인지를 비교합니다."
- (정책 국가별 키워드) "정책은 한국, 미국, 중국으로 나눠, 나라마다 어떤 키워드가 나오는지 봅니다. [예: 어느 나라의 정책 문서가 어떤 기술을 다루는지]"
- (기간 단위 주간) "기간을 주간으로 바꾸면 평소와 달라진 키워드와 흐름이 나옵니다."
- "키워드 사전만 바꾸면 **내 분야의 용어로** 쓸 수 있습니다. [바이오나 에너지 분야로 바꿔 쓸 수도 있습니다.]"

### 4. 내가 고친 부분 (3:15 ~ 4:00)
- "[제가 한 것은 다음과 같습니다.]"
- "**기간을 입력해 수집하는 `monitor.py`**를 만들었습니다. 자동 수집이 돌지 않아도 쓸 수 있도록 한 것입니다."
- "**대시보드를 한 화면 카드 구성으로 바꿨습니다.** 탭을 눌러야 보이던 정보를 한 번에 읽도록 하고, 어려운 용어를 풀어 쓰고 그래프를 넣었습니다."
- "**정책에 국가별 키워드와 문서 목록**을 넣었습니다. 정책 쪽이 빈약해 보인다는 지적을 반영한 것입니다."
- "**키워드 사전을 v2, v3로 보강**했고, 오탐 위험이 큰 후보는 영향 문서 수를 재 보고 일부러 뺐습니다."
- "공개하기 전에 저작권과 개인정보를 점검하고, 합성 샘플로 만든 배포용 데모를 따로 만들었습니다."

### 5. 써 보니 아쉬운 점 (4:00 ~ 4:45)
- "뉴스 피드는 최근 기사만 줘서 **먼 과거와는 비교할 수 없습니다.** 자료가 쌓여야 의미가 커집니다."
- "**사전에 있는 용어만 셉니다.** 없는 용어는 놓치고, 스쳐 가는 언급도 한 건으로 셉니다. 정확도는 측정하지 못했습니다."
- "정책 자료에는 시상식이나 환경 규정처럼 **ICT가 아닌 문서**가 많아서 키워드가 잡히지 않는 문서가 많았습니다. 다음에는 ICT 여부를 가려내는 규칙이 필요합니다."
- "입력은 명령줄이라서 **브라우저에서 자료를 직접 붙여 넣는 기능은 없습니다.**"
- (마무리, README 맨 위) "저장소와 배포 주소는 README 맨 위에 있고, 화면 설명은 `docs/dashboard_guide.md`에 있습니다."

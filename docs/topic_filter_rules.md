# 비ICT 기사 제외 규칙 설계

**상태: 설계안(미구현).** 정제·중복 제거는 B 담당(`normalize.py`, #9)이라 구현 전에 B와 합의가 필요하다. 이 문서는 `docs/data_dictionary.md` §3의 `exclusion_reason=not_target_topic`(디지털·ICT 범위에 해당하지 않는 문서)을 어떻게 판정할지 정한다.

## 1. 왜 필요한가

일반 종합 피드(ZDNet Korea, 전자신문)는 ICT와 무관한 기사를 섞어 준다. 2026-10-17에 수집한 150건 중 키워드가 하나도 안 잡힌 비ICT 기사가 이런 것들이었다.

| 유형 | 사례(제목) |
|---|---|
| 부고·인사·동정 | `[부고] … 빙부상`, `[인사] 과학기술정보통신부`, 두산 CFO 승진 |
| 에너지·금융 | 석유 최고가격 동결, 농협의 MBK 거래 |
| 지역 행사·유통 | 일자리박람회, 푸드페스타, 해외 투자 유치 |
| 콘텐츠 | 중국 드라마 독점 공개 |

이런 문서는 문서 비율(`키워드 문서 수 ÷ 분석 문서 수`)의 **분모**를 키워 모든 키워드의 비율을 낮춘다. 기획안 §4는 분모에 "키워드가 없는 분석 완료 문서"도 포함하라고 하므로, **ICT 문서인데 키워드가 없는 것**과 **ICT가 아닌 것**을 구분하는 규칙이 필요하다.

## 2. 설계 원칙

1. **추적 키워드와 독립적으로 판정한다.** "키워드가 없으니 제외"는 금지다. 그렇게 하면 모든 문서가 키워드를 가진 셈이 되어 비율이 항상 100%에 가까워진다. 판정은 **비ICT임을 가리키는 신호**가 있을 때만 제외한다.
2. **의심스러우면 유지한다.** 잘못 제외하면 근거가 사라지고, 잘못 유지하면 분모만 조금 커진다. 앞쪽이 더 나쁘므로 **제외 조건은 보수적으로**, 애매한 문서는 유지한다.
3. **지우지 않고 기록한다.** 제외 문서도 `documents.csv`에 `status=excluded`, `exclusion_reason=not_target_topic`으로 남기고, **어떤 규칙이 작동했는지**를 별도 기록(§6)에 남긴다.
4. **결정적이다.** 같은 입력과 같은 규칙 파일이면 같은 결과가 나온다(완료 기준 C8). 규칙은 버전이 있는 파일이다. 모델·LLM 판정은 쓰지 않는다.
5. **정책 자료에는 적용하지 않는다.** 정책 출처(정부·공공기관의 디지털·ICT 정책 문서)는 선정 단계에서 범위를 좁혔으므로 이 규칙은 `source_type=news`에만 쓴다.

## 3. 처리 순서

기획안 §4의 단계에서 **정제 뒤, 중복 제거 앞**에 넣는다.

```
수집 → 정제 → [주제 판정] → 중복 제거 → 추출 → 집계
```

중복 제거보다 **먼저** 해야 하는 이유: 중복 제외 문서의 `duplicate_of`는 `status=analyzed`인 대표 문서를 가리켜야 한다(`docs/data_dictionary.md` §2, 검증기가 검사). 비ICT로 제외된 문서가 대표가 되면 이 규칙을 어긴다. 주제 판정에서 먼저 걸러 대표 후보에서 빼야 한다.

한 문서가 여러 사유에 걸리면 **먼저 적용하는 규칙의 사유**를 남긴다. 순서는 `no_text` → `no_published_date` → `out_of_period` → `not_target_topic` → `duplicate`다.

## 4. 판정 규칙

판정 대상 텍스트는 **제목과 요약·본문**이며, 실제 분석 범위(`analysis_scope`)와 같다. 제목만 분석한 문서는 제목만 본다.

### R1 — 제목 태그 (명백한 비주제 공지)

제목이 `[부고]`, `[부음]`, `[인사]`, `[동정]`, `[포토]`, `[운세]` 같은 **말머리**로 시작하면 제외한다. 괄호는 `[ ]`, `【 】`, `( )`를 모두 본다.

- 이유: 매체가 스스로 붙이는 형식 표지라 오판이 거의 없다.
- 주의: `[인사] 과학기술정보통신부`는 인사 공지이지 기술 동향이 아니므로 제외한다. 다만 직책명에 "인공지능" 같은 키워드가 들어 있어 키워드 문서가 빠지게 된다(§7).

### R2 — 비ICT 영역어 우세

다음을 **모두** 만족하면 제외한다.

1. **비ICT 영역어**가 1개 이상 있다 (예: 석유, 휘발유, 승진, 빙부상, 일자리박람회, 푸드, 드라마, 공시, 횡령, 대출).
2. **강한 ICT어**가 하나도 없다 (예: 소프트웨어, 반도체, 통신, 데이터, 클라우드, 보안, 서버, 프로그래밍, 오픈소스, GPU).

**약한 ICT어**(기술, 디지털, 플랫폼, 정보, 스마트, 웹, 앱, 게임)는 일반 기사에도 흔하므로 **판정에 쓰지 않는다**(문서를 보호하지도 제외하지도 않는다). 예를 들어 푸드페스타 기사의 "플랫폼", "기술" 때문에 유지되는 일을 막기 위해서다.

### R3 — 출처 섹션 정보 (참고만)

피드의 `category` 태그(ZDNet의 `홈/모바일`, `방송/통신`, `디지털경제`, `IT 일반` 등)는 **판정에 쓰지 않는다.** 실제 데이터에서 석유 가격과 농협 기사에 `디지털경제`, 두산 CFO 승진 기사에 `IT 일반`이 붙어 있었다. 섹션 태그는 신뢰할 수 없어 제외 근거로 삼지 않는다. 나중에 보조 신호로 검토할 수는 있다.

### 유지(기본값)

R1·R2에 걸리지 않으면 유지한다. ICT 관련성이 불분명한 문서(예: 앤트로픽 매출, 아이폰 출시 소식)도 유지한다. 유지한 문서 중 키워드가 없는 것은 §7의 한계로 보고한다.

## 5. 규칙 파일 형식 (제안)

`config/topic_rules.csv`에 규칙을 두고, 코드에는 규칙 내용을 넣지 않는다. 규칙을 바꿀 때마다 `rules_version`을 올린다.

| 열 | 내용 |
|---|---|
| `rule_id` | `R1`, `R2` 등 |
| `kind` | `title_tag` / `domain_term` / `strong_ict_term` |
| `pattern` | `title_tag`는 말머리 낱말, 나머지는 낱말 하나. 영문 약어는 단어 경계로 일치 |
| `rules_version` | 예: `t1` |
| `note` | 근거와 추가한 날 |

사전(`config/keywords.csv`)과는 **별개 파일**이다. 추적 키워드를 바꿔도 제외 결과가 바뀌지 않아야 한다.

## 6. 기록

- `documents.csv`: `status=excluded`, `exclusion_reason=not_target_topic` (데이터 사전에 이미 있는 값)
- `topic_exclusions.csv` (실행 결과 폴더, 제안): `document_id`, `rule_id`, `matched_terms`(JSON 배열), `rules_version`. 데이터 사전의 `documents.csv` 열은 바꾸지 않는다.
- 실행 기록(`collect_log.json`)에 사유별 제외 건수를 포함한다. 대시보드는 이미 제외 건수를 표시한다.

## 7. 실제 자료에 시험한 결과

2026-10-17에 수집한 뉴스 150건(10월 기간 138건)에 이 설계를 적용해 보았다. 이 결과는 설계 타당성을 보는 **사례 확인**이며 정확도 수치가 아니다.

| 항목 | 결과 |
|---|---|
| 제외 후보 | 12건 (R1 3건: 부고 1, `[인사]` 2 / R2 9건) |
| R2 9건 | 일자리박람회, 수원 투자 유치, 농협 거래, 석유 가격, 푸드페스타 2건, 넷플릭스 구조조정, 두산 CFO 승진, 중국 드라마 공개 |
| 키워드가 잡힌 문서 중 제외 | **2건.** `[인사] 과학기술정보통신부` 인사 공지 2건이 R1에 걸렸고, 본문에 직책명으로 "인공지능"이 들어 있어 키워드가 잡혀 있었다. 인사 공지는 기술 동향이 아니라 제외가 맞다고 판단했지만, 키워드 문서가 빠지는 경우이므로 R1을 적용할 때 사람이 확인할 대상이다 |
| 눈으로 본 경계 사례 | "싱가포르서 펼친 수원 투자 지도"(지역 투자 유치), "넷플릭스는 왜 1000명 자르고…"(미디어·OTT). ICT 인접 영역이라 제외가 맞는지 판단이 갈린다 |
| 유지했지만 비ICT로 의심되는 것 | 두산에너빌리티 CFO 승진 기사(본문에 AI 언급이 있어 강한 ICT어가 있음), LGD·엔솔 불성실공시, 엔젤로보틱스 대표이사 선임 |

제외 후보 12건은 모두 전자신문·ZDNet 기사다. 긱뉴스(개발자 커뮤니티)는 비ICT 기사가 거의 없고, 대신 **ICT 문서인데 사전에 없어 키워드가 안 잡힌 것**(트랜스포머, 암호, 프로그래밍 언어)이 많다. 이 두 경우를 구분하는 것이 이 규칙의 핵심이다 — 후자는 제외하지 않는다(`docs/news_quality_review.md` 참조).

## 8. 한계

1. **낱말 목록은 사람이 고른 것**이라 빠진 비ICT 영역(스포츠, 연예, 날씨 등)이 있다. 수집 자료가 늘면 목록을 보강해야 하며, 이때 규칙 버전을 올리고 이전 결과와 다름을 기록한다.
2. **유지 기본값**이므로 비ICT 기사가 일부 남는다. 남은 비ICT 기사는 분모를 키워 비율을 약간 낮춘다.
3. 제외를 하면 분모가 줄어 **비율이 올라간다.** 이는 의도한 효과지만, 보고서에는 제외 전후의 분석 문서 수와 제외 사유별 건수를 함께 적어야 한다.
4. 사실상 한국어 기사용이다. 영어 출처(정책 쪽)에는 쓰지 않는다.
5. 이 문서는 **설계**다. 정확도, 재현율 같은 성능은 측정하지 않았다.
